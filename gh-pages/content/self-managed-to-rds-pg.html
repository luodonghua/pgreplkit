Overview

You are moving from a self-managed PostgreSQL server (on-prem, EC2, or a VM) to Amazon RDS for PostgreSQL, using logical replication so the cutover downtime is only the final drain-and-switch. Logical replication works across major versions, so this is also the recommended path for a version upgrade at the same time.

Direction of the connection RDS (the subscriber) makes an outbound connection to your self-managed server (the publisher) on port 5432. Your firewall / security group and the source's pg_hba.conf must allow the RDS instance's address. If RDS is in a private subnet, it reaches your data center over VPN or Direct Connect.
Physical seeds don't apply here RDS Snapshot Restore and Aurora Fast Clone only work when both sides are the same AWS engine. From self-managed, use Replication Copy (simplest) or a pg_dump seed (for large data / parallel load).
