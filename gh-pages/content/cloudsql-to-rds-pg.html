Overview

You are migrating from Google Cloud SQL for PostgreSQL to Amazon RDS for PostgreSQL — a cross-cloud move. Logical replication is the right tool: it works between any two PostgreSQL servers that can reach each other on the network, regardless of provider or major version. Physical seeds (snapshot/clone) are provider-specific and do not apply, so use Replication Copy or a pg_dump seed.

Enable logical decoding on Cloud SQL (the source) Set the cloudsql.logical_decoding = on database flag on the Cloud SQL instance and restart it. Grant the REPLICATION attribute to your migration user.
bash — gcloud 
gcloud sql instances patch MY_CLOUDSQL_INSTANCE \
  --database-flags=cloudsql.logical_decoding=on
# then restart when prompted; verify:
#   SHOW wal_level;   -- expect: logical
Cross-cloud networking is the hard part Cloud SQL is the publisher; the RDS instance (subscriber) must open an outbound connection to Cloud SQL on 5432. Either expose Cloud SQL with a public IP and add the RDS NAT/egress address to Cloud SQL's authorized networks (encrypt with SSL), or connect privately over a VPN / Cloud Interconnect between GCP and AWS. Test reachability before creating the subscription:
bash — from the RDS side / a host in the RDS VPC 
psql "host=CLOUDSQL_IP port=5432 user=repluser dbname=appdb sslmode=require" -c "select 1"
