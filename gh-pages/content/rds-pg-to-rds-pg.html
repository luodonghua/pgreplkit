Overview

Both sides are Amazon RDS for PostgreSQL. Because they share a platform, you get an extra, very fast option: seed the target with an RDS snapshot restore (which preserves LSN continuity) and resume logical streaming from the exact seed point. For smaller databases, plain Replication Copy is simpler; pg_dump sits in between for parallel logical loads.

Enable logical WAL on the source Set rds.logical_replication = 1 in the source DB parameter group. It is a static parameter, so the instance must be rebooted for it to take effect. Confirm with SHOW rds.logical_replication; (should return on).
Networking The target instance (subscriber) connects to the source (publisher) on 5432. Keep both in the same VPC where possible, connect to the source's private address, and allow the VPC CIDR on the source security group.
Snapshot seed and major-version upgrades The snapshot restore lands green on the source's major version. That also enables an upgrade: capture the seed LSN while green is still on the old version, upgrade green in place, then wire replication (logical CDC streams old → new). See the note in the snapshot setup. A logical Replication Copy or pg_dump is the alternative if you'd rather not upgrade in place.
