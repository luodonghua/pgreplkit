Set up replication — Aurora Fast Clone

Aurora's fast cloning is copy-on-write against the shared cluster storage, so a clone is ready in minutes regardless of data size. The clone preserves LSN continuity, so you resume logical streaming from the clone's start position exactly once.

Same major version only A clone is always the same major version as the source. For a cross-version move use Replication Copy or pg_dump. (To combine the clone with a major upgrade, capture the seed LSN before upgrading the clone — see the note at the end.)
1 Prepare the SOURCE: publication, then slot
psql — on SOURCE writer (order matters) 
CREATE PUBLICATION pub_app FOR TABLE customers, orders;
-- (or FOR TABLES IN SCHEMA app;  on PG 15+)

SELECT pg_create_logical_replication_slot('sub_app', 'pgoutput');
Publication before slot, and slot before clone — so the clone contains the slot and the source keeps all WAL after the slot's position.
2 Fast-clone the cluster and add a writer
bash — AWS CLI 
aws rds restore-db-cluster-to-point-in-time \
  --db-cluster-identifier green-clone \
  --source-db-cluster-identifier blue-cluster \
  --restore-type copy-on-write \
  --use-latest-restorable-time \
  --db-subnet-group-name my-subnet-group \
  --vpc-security-group-ids sg-0123456789 \
  --region us-east-1

aws rds create-db-instance \
  --db-cluster-identifier green-clone \
  --db-instance-identifier green-clone-1 \
  --db-instance-class db.r6g.large \
  --engine aurora-postgresql \
  --region us-east-1
aws rds wait db-instance-available \
  --db-instance-identifier green-clone-1 --region us-east-1
Networking The clone's writer must reach the source writer on 5432. Set the source writer's private address as the subscription host and allow the VPC CIDR on the source security group. Aurora public endpoints can hairpin to public IPs inside a VPC.
3 Capture the seed LSN on the CLONE
psql — on the CLONE writer 
SELECT aurora_volume_logical_start_lsn();
--  aurora_volume_logical_start_lsn
--  0/6188A58            <- save this value
Aurora vs RDS function On Aurora use aurora_volume_logical_start_lsn(). The RDS function rds_tools.logical_seed_lsn() does not exist on Aurora. aurora_volume_logical_start_lsn() is available on Aurora PostgreSQL 16, 17 and 18.
4 Wire the subscription and advance the origin
psql — on the CLONE writer 
CREATE SUBSCRIPTION sub_app
  CONNECTION 'host=SOURCE_WRITER_PRIVATE_IP port=5432 user=repluser password=SECRET dbname=appdb'
  PUBLICATION pub_app
  WITH (copy_data = false, create_slot = false, enabled = false, slot_name = 'sub_app');

SELECT 'pg_' || oid AS origin FROM pg_subscription WHERE subname = 'sub_app';

-- advance to the seed LSN from step 3 (the exactly-once boundary)
SELECT pg_replication_origin_advance('pg_16417', '0/6188A58');

ALTER SUBSCRIPTION sub_app ENABLE;
Same idea as any physical seed: the origin advance says "I already hold everything up to the clone point; stream only what came after," so the clone and the live stream join with no gap and no duplicates.
Combining with a major-version upgrade To also upgrade (e.g. 17 → 18): do steps 1–3 while the clone is still the old version and save the seed LSN before upgrading. Then major-upgrade the clone, and only afterwards run step 4. The seed LSN is on the source's timeline, so upgrading the clone doesn't invalidate it. This is the same clone → upgrade → subscribe pattern AWS Blue/Green Deployments use.
