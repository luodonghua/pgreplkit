Create the replication user (on the source)

The subscriber connects to the source as this role, so create it on the source (publisher). On self-managed PostgreSQL you set the REPLICATION attribute directly.

psql — on SOURCE (self-managed) 
-- login role with the REPLICATION attribute (needed to read replication slots)
CREATE ROLE repluser WITH LOGIN REPLICATION PASSWORD 'strong-secret';

-- allow it to read the data being replicated
GRANT USAGE ON SCHEMA app TO repluser;
GRANT SELECT ON ALL TABLES IN SCHEMA app TO repluser;
ALTER DEFAULT PRIVILEGES IN SCHEMA app GRANT SELECT ON TABLES TO repluser;  -- future tables too

Then permit the role to connect for replication in pg_hba.conf and reload:

pg_hba.conf — on SOURCE (adjust the subscriber CIDR) 
# TYPE  DATABASE  USER      ADDRESS        METHOD
host    appdb     repluser  10.0.0.0/24    scram-sha-256
# then:  SELECT pg_reload_conf();
On the subscriber (target) The role that runs CREATE SUBSCRIPTION needs elevated rights: on PG 16+ grant it pg_create_subscription plus CREATE on the database; on PG < 16 it must be a superuser. (Target is RDS/Aurora here — see the target row of the prerequisites table above.)
