Create the replication user (on the source)

The subscriber connects to the source as this role, so create it on the source (publisher). On RDS and Aurora you cannot set the REPLICATION attribute directly — there is no superuser. Instead you grant the managed rds_replication role, connecting as your RDS/Aurora master user.

psql — on SOURCE (RDS / Aurora), as the master user 
CREATE ROLE repluser WITH LOGIN PASSWORD 'strong-secret';
GRANT rds_replication TO repluser;      -- the managed replication privilege (not the attribute)

GRANT USAGE ON SCHEMA app TO repluser;
GRANT SELECT ON ALL TABLES IN SCHEMA app TO repluser;
ALTER DEFAULT PRIVILEGES IN SCHEMA app GRANT SELECT ON TABLES TO repluser;  -- future tables too
No pg_hba.conf to edit On RDS/Aurora access is controlled by security groups and the DB's parameter group, not a hand-edited pg_hba.conf. Allow the subscriber to reach the source on 5432 via the security group.
On the subscriber (target, RDS/Aurora) The role that runs CREATE SUBSCRIPTION needs rds_superuser (PG < 16) or rds_replication + pg_create_subscription (PG 16+) — see the target row of the prerequisites table above.
