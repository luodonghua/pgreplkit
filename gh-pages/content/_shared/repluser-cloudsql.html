Create the replication user (on the source)

The subscriber connects to the source as this role, so create it on the source (publisher). On Cloud SQL you create the role and grant the cloudsqlsuperuser/REPLICATION capability, connecting as an admin user.

psql — on SOURCE (Cloud SQL), as an admin user 
CREATE ROLE repluser WITH LOGIN REPLICATION PASSWORD 'strong-secret';
-- (Cloud SQL permits the REPLICATION attribute for the admin-managed role)

GRANT USAGE ON SCHEMA app TO repluser;
GRANT SELECT ON ALL TABLES IN SCHEMA app TO repluser;
ALTER DEFAULT PRIVILEGES IN SCHEMA app GRANT SELECT ON TABLES TO repluser;  -- future tables too
Access control Cloud SQL access is governed by authorized networks (public IP) or a private IP over VPN/Interconnect, plus SSL — not a hand-edited pg_hba.conf. Ensure the AWS subscriber can reach Cloud SQL on 5432 (see the networking note above).
On the subscriber (target, RDS/Aurora) The subscribing role needs rds_superuser (PG < 16) or rds_replication + pg_create_subscription (PG 16+) — see the target row of the prerequisites table above.
