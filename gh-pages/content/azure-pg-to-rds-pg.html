Overview

You are migrating from Azure Database for PostgreSQL – Flexible Server to Amazon RDS for PostgreSQL — a cross-cloud move. Flexible Server supports native logical replication, so use Replication Copy or a pg_dump seed. Provider-specific physical seeds do not apply.

This guide covers Flexible Server only It does not cover the retired Single Server offering or the distributed Cosmos DB for PostgreSQL (Citus). If you are on Single Server, migrate to Flexible Server (or dump/restore) first, then replicate.
Enable logical replication on Azure (the source) On Flexible Server set the server parameter wal_level = logical and ensure max_replication_slots and max_wal_senders are large enough, then restart the server. Use the azure_pg_admin role and grant REPLICATION to the migration user (Flexible Server has no classic superuser).
bash — az CLI 
az postgres flexible-server parameter set \
  --resource-group MY_RG --server-name MY_AZ_SERVER \
  --name wal_level --value logical
# then restart:
az postgres flexible-server restart \
  --resource-group MY_RG --name MY_AZ_SERVER
#   SHOW wal_level;   -- expect: logical
Cross-cloud networking Azure Flexible Server is the publisher; the RDS subscriber connects outbound to it on 5432. Use public access + Azure firewall rules (with SSL), or a site-to-site VPN for private access. Verify reachability from the RDS side first:
bash — from the RDS VPC 
psql "host=MY_AZ_SERVER.postgres.database.azure.com port=5432 user=repluser dbname=appdb sslmode=require" -c "select 1"
